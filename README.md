# יומן אתר

אפליקציה לניהול לוגיסטיקה באתר הקמה סולארי, שפותחה ונבדקה באתר עין תמר של בלקטריק ישראל.
מלאי מתעודות משלוח, ניפוקי ברגים וכלי עבודה עם חתימה, ספירות, תעודות בטון, מאזן פאנלים,
רכש (BOM / EBOQ, הזמנות רכש, בקשות מול הזמנות, תאריכי אספקה), סטטוס התקדמות, עובדים יומיים וסיכום לקבלן.
עברית, RTL, מותאמת לטלפון.

**גרסה נוכחית: 52** (בשלושת המופעים מ-28.10.2026)

## עדכון גרסה

1. לערוך ב-`src/` ולהעלות את `APP_VERSION` (ב-`src/js/08-settings.js`), ואז `npm run build`.
2. `npm test` (בדיקות, כולל רינדור ברוחב 400px בלי גלילה אופקית ובלי שגיאות JS).
3. בדיקת תחביר: `node --check` על הסקריפט המחולץ.
4. גיבוי הקובץ החי של כל מופע לפני פרסום.
5. `npm run build:sites`, ולפרסם כל `dist/<אתר>.html` למופע שלו, **בלי** להעביר `capabilities` (כך ההצהרה הקיימת נשמרת).
6. `git tag vNN` ו-push לתגית.

## בדיקות

```
npm test
```

דורש Node 20 ומעלה ו-Playwright עם Chromium. הבדיקות טוענות את `artifact/yoman.html` עם `window.claude` מדומה (`tests/mock-claude.js`: מאגר בזיכרון עם כללי הגישה, משתמש בתפקיד בעלים/עורך/צופה). כל בקשת רשת חסומה בבדיקות.
הבדיקות רצות גם ב-GitHub Actions (`.github/workflows/tests.yml`): כל יום ב-04:00 שעון ישראל, ובכל push ו-PR. בדיקה שנכשלת שולחת מייל לבעל הריפו.
להרצה מול קובץ אחר: `APP_FILE=path/to/file.html npm test`.

מה נבדק (28 בדיקות): טעינה בלי שגיאות ברוחב 400px; פס «אין חיבור»; שמירת הגדרות בלי דריסה; שמירת בקשת רכש של עורך; PDF לניפוק חתום; חישובי מלאי, «מי מחזיק מה» ובקשות מול הזמנות; זרימות מלאות (`tests/flows.test.js`): קליטת תעודה, ניפוק ברגים עם חתימה ובלי, ספירה מהירה בקרטונים, מאזן פאנלים (ספייר, פער, קצב, שבירה, תנועות אחרי המאזן); למידת כמות בקרטון בלי לדרוס את ה-BOM; 36 חלונות קופצים נפתחים ונסגרים (כולל Escape); Supabase: סכמה, ייבוא והרשאות (על PGlite); סביבת הפיתוח.
הבא בתור: בדיקת AI על 20 עד 30 תעודות אמיתיות, בלי ת.ז. ומחירים, מחוץ לריפו. התוכנית: [`docs/ai-test.md`](docs/ai-test.md).

## מגבלות ידועות

- **5,000 מסמכים לכל מופע** (מגבלת הפלטפורמה; יצירה מעבר לכך נכשלת). היום כ-500 בעין תמר. בקצב הנוכחי זה מספיק לפרויקט אחד, לא לכמה שנים.
- 256KB למסמך; עד 64 האזנות פתוחות לכל תצוגה.
- כל הנתונים נטענים בפתיחה. נמדד ב-28.10 (`node tools/loadtime.js`, טלפון איטי מדומה, CPU פי 4): פתיחה וציור בכ-1.0 שניות עם 500 רשומות, 1.3 עם 2,000 ו-1.6 עם 5,000 (התקרה). הזמן ברשת עצמה (המאגר של claude.ai) לא נמדד כאן. טעינה חלקית (רק 3 חודשים) **לא** מומלצת כרגע: המלאי, מאזן הפאנלים ובקשות מול הזמנות מחושבים מכל ההיסטוריה, וחיתוך ישבש אותם. אם הנפח יגדל, הפתרון הוא מסמכי סיכום (יתרה סגורה לתאריך) ולא חיתוך.
- כל אתר הוא עותק נפרד, ושינוי גרסה מתפרסם לכל מופע בנפרד. **מגרסה 61 יש גם גרסת ענן:** אותו קוד על Supabase (מאגר אחד לכל האתרים, כניסה במייל, הרשאה לכל אתר) מאוחסן ב-Vercel, עם מסך חברה. הסכמה וההרשאות ב-`supabase/`, הבנייה `npm run build:cloud`, ההגדרות `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_ANON_KEY` בזמן הבנייה.

## התראות (push notifications)

לא אפשרי בתוך artifact. התראות שמגיעות לטלפון כשהאפליקציה סגורה דורשות service worker ושרת push עם מפתחות VAPID, והדף של ה-artifact רץ בתוך מסגרת של claude.ai שלא מאפשרת לרשום service worker משלו. באייפון זה עובד רק מאפליקציה שהותקנה למסך הבית.
מה צריך: אחסון עצמאי (דומיין משלנו, PWA), שרת או פונקציה ששולחת את ההתראות (למשל Supabase Edge Functions או Vercel), וטבלת מנויים לפי משתמש. זה תלוי במעבר ל-Supabase אחרי הפיילוט.
עד אז: התזכורות בתוך האפליקציה (למשל «סוף יום: דווח ביצוע») והודעות הוואטסאפ שהאפליקציה מכינה.

## Vite: פיתוח ובנייה

```
npm install
npm run dev     # http://localhost:5173
```

מגיש את האפליקציה מ-`src/` עם `window.claude` מדומה ונתוני הדוגמה הסינתטיים, וטוען מחדש בכל שמירה. פרמטרים: `?role=editor`/`viewer`, `?empty=1`, `?site=moledet`.
שלב 2 (בוצע 28.10): 42 המשתנים שקובץ אחד מגדיר וקובץ אחר משנה (למשל `deliveries`, `kit`, `orders`, `DB`) מרוכזים באובייקט אחד, `shared` (מוגדר בראש `core.js`), כי מודול לא יכול לשנות משתנה שיובא מקובץ אחר. השינוי נעשה בכלי שמבין טווחים (eslint-scope), לא בחיפוש-והחלפה: 854 החלפות, ואותה רשימת שמות לא מוגדרים לפני ואחרי. כל הבדיקות עוברות.
שלב 3 (בוצע 28.10, באישור ישי): כל קובץ ב-`src/js` הוא מודול. פונקציות מיוצאות (`export`) כמו שהן; משתנים מוכרזים `export let` בראש הקובץ, וההשמה שלהם יחד עם שאר הקוד שרץ בטעינה נמצאת ב-`__init()` של הקובץ. `main.js` מריץ את ה-`__init` של כל הקבצים בסדר הישן, ואז מציב את הפונקציות על `window`, כי הכפתורים ב-HTML והבדיקות קוראים להן בשם. כך סדר הריצה זהה לקובץ המשורשר, וכל import מפורש בראש הקובץ. ההמרה נעשתה בכלי שמבין טווחים (eslint-scope), לא ידנית; אין קובץ שכותב למשתנה של קובץ אחר (זה עבר ל-`shared` בשלב 2).
`npm run build` מריץ `vite build` (עם vite-plugin-singlefile) וכותב את `artifact/yoman.html`; `npm test` נכשל אם הקובץ לא תואם לבנייה. כל 29 הבדיקות עוברות על הקובץ הבנוי.
