# יומן אתר

אפליקציה לניהול לוגיסטיקה באתר הקמה סולארי, שפותחה ונבדקה באתר עין תמר של בלקטריק ישראל.
מלאי מתעודות משלוח, ניפוקי ברגים וכלי עבודה עם חתימה, ספירות, תעודות בטון, מאזן פאנלים,
רכש (BOM / EBOQ, הזמנות רכש, בקשות מול הזמנות, תאריכי אספקה), סטטוס התקדמות, עובדים יומיים וסיכום לקבלן.
עברית, RTL, מותאמת לטלפון.

**גרסה נוכחית: 52** (בשלושת המופעים מ-28.10.2026)

| תיקייה | מה |

## עדכון גרסה

1. לערוך ב-`src/` ולהעלות את `APP_VERSION` (ב-`src/js/08-settings.js`), ואז `npm run build`.
2. `npm test` (בדיקות, כולל רינדור ברוחב 400px בלי גלילה אופקית ובלי שגיאות JS).
3. בדיקת תחביר: `node --check` על הסקריפט המחולץ.
4. גיבוי הקובץ החי של כל מופע לפני פרסום.
5. `npm run build:sites`, ולפרסם כל `dist/<אתר>.html` למופע שלו, **בלי** להעביר `capabilities` (כך ההצהרה הקיימת נשמרת).
6. `git tag vNN` ו-push לתגית.

## בדיקות

```
npm test
```

דורש Node 20 ומעלה ו-Playwright עם Chromium. הבדיקות טוענות את `artifact/yoman.html` עם `window.claude` מדומה (`tests/mock-claude.js`: מאגר בזיכרון עם כללי הגישה, משתמש בתפקיד בעלים/עורך/צופה). כל בקשת רשת חסומה בבדיקות.
הבדיקות רצות גם ב-GitHub Actions (`.github/workflows/tests.yml`): כל יום ב-04:00 שעון ישראל, ובכל push ו-PR. בדיקה שנכשלת שולחת מייל לבעל הריפו.
להרצה מול קובץ אחר: `APP_FILE=path/to/file.html npm test`.

מה נבדק (21 בדיקות): טעינה בלי שגיאות ברוחב 400px; פס «אין חיבור»; שמירת הגדרות בלי דריסה; שמירת בקשת רכש של עורך; PDF לניפוק חתום; חישובי מלאי, «מי מחזיק מה» ובקשות מול הזמנות; זרימות מלאות (`tests/flows.test.js`): קליטת תעודה, ניפוק ברגים עם חתימה ובלי, ספירה מהירה בקרטונים, מאזן פאנלים (ספייר, פער, קצב, שבירה, תנועות אחרי המאזן).
הבא בתור: בדיקת AI על 20 עד 30 תעודות אמיתיות, בלי ת.ז. ומחירים, מחוץ לריפו. התוכנית: [`docs/ai-test.md`](docs/ai-test.md).

## מה נוסף בגרסה 52

- `lang="he"` ו-`dir="rtl"` על המסמך (קוראי מסך ותרגום; התצוגה לא השתנתה).
- פס «אין חיבור» כשאין אינטרנט, כשהחיבור למאגר נותק, כשהמאגר לא נטען (שמירה מקומית בלבד) או כשהנתונים מהמטמון יותר מ-45 שניות. כפתור «רענן».
- ספקים, ברקודים וכינויים נשמרים כמיזוג של השינוי בלבד ולא כדריסה של כל הרשימה.
- תיקון: עורך (לא בעלים) קיבל «השמירה נכשלה» בשמירת בקשת רכש, כי השמירה ניסתה לכתוב גם לרשימת הספקים שמותרת לבעלים בלבד. הבקשה נשמרת עכשיו תמיד; רשימת הספקים מתעדכנת רק אצל הבעלים.
- מטרות מגע של 44px לפחות (עבודה עם כפפות).
- PDF לכל ניפוק (ברגים או ציוד) עם החתימה, שם המקבל, הפריטים והתאריך. שם קובץ: `אתר_תאריך_מקבל_מספר.pdf`. ב«כל הניפוקים»: PDF אחד לתקופה עם עמוד לכל ניפוק חתום. בלי ת.ז. ובלי מחירים.
- כפתור «דוח שבועי»: דוח סטטוס לאתר (גרסה למנהלים וגרסה ליזם), כולל השוואת צילומי רחפן «אז מול עכשיו». בלי מחירים.

## מגבלות ידועות

- **5,000 מסמכים לכל מופע** (מגבלת הפלטפורמה; יצירה מעבר לכך נכשלת). היום כ-500 בעין תמר. בקצב הנוכחי זה מספיק לפרויקט אחד, לא לכמה שנים.
- 256KB למסמך; עד 64 האזנות פתוחות לכל תצוגה.
- כל הנתונים נטענים בפתיחה. טעינה חלקית (רק 3 חודשים) **לא** מומלצת כרגע: המלאי, מאזן הפאנלים ובקשות מול הזמנות מחושבים מכל ההיסטוריה, וחיתוך ישבש אותם. אם הנפח יגדל, הפתרון הוא מסמכי סיכום (יתרה סגורה לתאריך) ולא חיתוך.
- כל אתר הוא עותק נפרד, ושינוי גרסה מתפרסם לכל מופע בנפרד. מעבר למאגר מרכזי (Supabase) סוכם לאחרי הפיילוט.

## התראות (push notifications)

לא אפשרי בתוך artifact. התראות שמגיעות לטלפון כשהאפליקציה סגורה דורשות service worker ושרת push עם מפתחות VAPID, והדף של ה-artifact רץ בתוך מסגרת של claude.ai שלא מאפשרת לרשום service worker משלו. באייפון זה עובד רק מאפליקציה שהותקנה למסך הבית.
מה צריך: אחסון עצמאי (דומיין משלנו, PWA), שרת או פונקציה ששולחת את ההתראות (למשל Supabase Edge Functions או Vercel), וטבלת מנויים לפי משתמש. זה תלוי במעבר ל-Supabase אחרי הפיילוט.
עד אז: התזכורות בתוך האפליקציה (למשל «סוף יום: דווח ביצוע») והודעות הוואטסאפ שהאפליקציה מכינה.
